# Muse 客户端蓝牙配对设计

安卓设备作为 BLE 外围设备，Muse 手机 App 作为中央设备。小智服务端持有官方 SDK 的 `PairingSession`、`SetupController` 与设备身份；安卓只承载 BLE 广播、GATT 读写和通知，不解析配对凭证。服务端验证设备 token 后原子保存身份和配对数据，继续负责连接 Muse 和对话。

1. 管理员在 Muse 后台保存 SDK Token，选择在线安卓设备并开启短时配对窗口。服务端生成独立随机的一次性会话凭证，绑定指定设备、单次连接和过期时间；不在无认证的 kiosk 接口泄露凭证。
2. 已认证的设备通道接收配对请求，安卓请求蓝牙权限，检查设备支持 BLE 外围广播；使用官方 SDK 的服务和 RX/TX UUID 建立 GATT 服务，广播与服务端身份相同的 `MuseGadget` 名称。失败时向后台报告原因。
3. 安卓通过带认证、限流且有长度限制的双向通道转发 BLE 数据包、MTU、连接和断开事件。传输与请求必须按会话隔离，断线时关闭窗口、停止广播并清除 SDK 加密状态；BLE 数据顺序和通知确认必须保持。
4. 服务端通过适配官方 `Transport` 接口，将通知按 SDK 的 BLE 分包规则返回安卓，执行官方 `SetupController` 的握手、确认、Wi-Fi 扫描及设备凭证校验。验证成功后通过 SDK 的 commit 机制写入持久化目录，通知页面和安卓结束配对。
5. 页面显示正在等待、已配对、失败和过期；取消或重连时同时关闭两端资源。服务器重启、安卓进程退出和蓝牙断开均使会话失效；不能自动重新使用旧的一次性凭证。已有配对不能被无意覆盖。

通道认证和会话边界必须覆盖 WebSocket 的握手、每条消息、设备断线和后台取消。应限制包长度、队列、并发和窗口时长，禁止输出 token、原始 BLE 包或加密载荷到日志。只能在真实设备确认支持 BLE 广播及 Android 版本相应权限后称为可用；手机的网络配置不能由服务端虚报为已经连接。

测试需覆盖官方 SDK 配对向量、BLE 分片、MTU 变化、断开重连、乱序和过大数据、过期令牌、并发与取消，以及设备 token 校验失败时不覆盖旧凭证。最后用 Muse 手机 App、目标安卓硬件和实际网关进行端到端验证。
