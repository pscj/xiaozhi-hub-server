# 语音打断方式

Android 客户端在「设置 → 连接与语音 → 语音打断方式」选择模式，保存重连后生效：

- `keywords`：默认模式。思考、播报期间只接受单独说出的“停止”或“暂停”；空格和标点不影响匹配。“不要停止”“暂停功能是什么”等普通句子忽略，不打断、不进入对话模型。正常聆听时照常处理问题。
- `any`：原来的自由插话模式；有效的新问题触发打断并开始下一轮。
- `off`：回答期间客户端暂停上传语音，实际播完后恢复。

按钮和本地唤醒词继续使用原有 `abort` 流程。停止词依赖 VAD 结束判定和 ASR 识别，因此有识别延迟；“暂停”和“停止”都结束当前回答，不提供断点续播。设备播放回声继续经过原有回声过滤。

## 协议

客户端 `hello.features.speech_interrupt` 为 `keywords`、`any` 或 `off`。网关在回复的 `hello.features.speech_interrupt` 中返回 `true`，确认支持该策略。未声明模式的旧客户端保持原有自由插话行为。新客户端连接不支持此能力的旧网关时，会提示更新，并暂停回答期间的语音上传，避免意外继续自由插话。

网关发出 TTS/start（包括思考阶段）或 sentence_start 时，进入仅处理打断指令的阶段。客户端在此阶段开启指令收音时发送 `listen/start`，附带 `purpose: "interrupt"`、`mode: "realtime"`。服务器发完音频后仍保持该阶段，直到客户端实际播放完缓冲，再发送普通的 `listen/start` 恢复问题收音。恢复时丢弃排队录音，并使上一个阶段迟到的 ASR 结果失效，避免把回答期间的闲聊提交成下一轮问题。

停止词命中后，网关调用统一打断处理并清空排队录音，返回 `tts/stop`，带 `interrupted: true`、`reason: "stop_word"`。客户端立即清空播放缓冲，恢复正常聆听。停止词本身不发送 STT、不作为用户消息写进对话模型。后台 Agent 是否继续任务，仍取决于各模型原有的打断策略。

非自由插话模式不使用服务端 AEC 的“检测到人声立即打断”分支，防止绕过停止词筛选。两字停止词在回答期间使用较短的音频长度门槛；普通问题的短噪声门槛保持不变。

## 验证

`tests/core/test_speech_interrupt.py` 覆盖停止词及标点、否定和普通句子的误触发保护、设备回声、正常提问、自由插话、手动模式、关闭模式、短指令、迟到识别、AEC 旁路防护、能力协商，以及设备实际播完后的模式恢复。测试使用模拟 ASR 和连接，不访问真实模型或麦克风。
